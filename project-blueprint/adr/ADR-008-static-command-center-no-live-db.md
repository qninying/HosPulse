# ADR-008: Static Command Center, no live DB connection

**Status:** Accepted

## Context

The Command Center (a separate, internal build-tracking site from the HosPulse product itself)
needs to show real project state — story verification, guardrail enforcement, and eventually AI
agent run history — and is hosted on GitHub Pages from a public repository.

## Decision

The Command Center has zero runtime credentials and makes zero live database calls. All of its
data (`plan.json`, `progress.json`, `manifest.json`, and the newer `agent_runs.json`) are files
committed to the repo, generated by scripts run manually or by the platform's own sync (`Colaberry
Build Bot`) and read via `fetch()` at page load. `pipeline/export_agent_run_stats.py` queries real
production Postgres and writes a small, redacted, aggregate-only snapshot — counts and
timestamps, never raw rows — specifically so an agent's real run history can be shown without a
credentialed connection from a public static page.

## Consequences

- No `DATABASE_URL`, no Supabase key of any kind, has ever been or will be committed to this
  public repo for the Command Center's own use — a real secret exposure this decision structurally
  prevents, not just a policy against it.
- Data is honestly "as of last sync," never "live" — the Command Center's own UI states this
  plainly rather than implying real-time freshness it can't provide.
- Real production facts (an agent's run count, a story's verification state) can go stale between
  syncs. Accepted, since the alternative (a live credentialed connection from a public page) is a
  materially worse trade.
